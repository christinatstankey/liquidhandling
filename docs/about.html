About

The problem

Safety Data Sheets tell you a reagent is flammable, irritating, or hazardous. They do not tell your liquid handler to pre-wet tips three times before aspirating volatile liquids, to use wide-bore tips for viscous solutions, or to slow down aspiration to keep detergents from foaming.

That knowledge lives in the heads of experienced bench scientists. It is passed on verbally, buried in methods sections, or learned by ruining an experiment. The gap between "safe to handle" and "correct to pipette" is where liquid handlers can fail.

What this does

This database is a transparent rules layer between chemical evidence and robot instructions. Each reagent is keyed by CAS number and has a structured JSON profile built from Sigma-Aldrich SDS facts, PubChem properties, and ChEBI roles. A declarative YAML rules engine maps those fields to handling instructions. Every rule cites a reagent property or a published source.

The output is a JSON handling profile a liquid handler can consume directly:

  • Aspiration speed and technique (reverse pipetting, pre-wet cycles, wide-bore tips)
  • Container and storage controls (amber handling, dry storage, flammable cabinet)
  • Preparation requirements (make fresh, warm to room temperature, minimize light or air exposure)
  • Safety controls (fume hood, gloves, waste stream, segregation)

Each instruction carries a confidence level derived from the evidence chain. SDS-extracted, PubChem-derived, and ChEBI-backed facts are high confidence. Field consensus and placeholder fallback sources are lower confidence, and uncorroborated tacit flags remain null rather than guessing.

Data pipeline

The current corpus is Sigma-Aldrich reagents with resolvable CAS numbers, sourced from frequency-ranked Sigma citations in Cell Press STAR methods sections. The pipeline parses local SDS PDFs, enriches the resulting records, applies manual corrections, validates schema v2.0, and regenerates static handling profiles under data/handling/. Source types are explicitly tracked so downstream consumers can evaluate reliability:

Source typeWhat it providesConfidence
sds_phrase Literal phrase match in SDS §7/§10 (e.g., "hygroscopic", "flammable") high
ghs_hcode GHS hazard code from SDS §2 (e.g., H228 → flammable solid) high
storage_class ADR storage class from SDS §7 (e.g., 3 → flammable liquid) high
pubchem Numeric properties and public hazard annotations (e.g., vapor pressure, flash point, LogP) high
chebi ChEBI ontology role (e.g., CHEBI:25944 → fluorophore → light-sensitive) high
rule_derived Flag inferred from another sourced flag by a declared rule (e.g., fluorophore → light-sensitive) inherits
tacit_knowledge Bench-practice rule source from the curated tacit-knowledge taxonomy low
claude_inference Fallback marker for not-yet-assessed or legacy MVP fields; new bulk records do not invent true/false values from it low

What it isn't

This is not an SDS database, EH&S compliance tool, or general protocol library. It is scoped right now to Sigma-Aldrich small molecules, solvents, dyes, salts, fixatives, powders, and detergents with CAS numbers.

Out of scope by design: enzymes and biologics from specialty vendors, cell culture handling, buffer preparation workflows, and freeform protocol text. Those require different evidence paths than the current CAS/Sigma SDS workflow, so they were excluded rather than mixed into the small-molecule pipeline.

Data sourced from Sigma-Aldrich SDS sheets, PubChem, ChEBI, and cited handling rules. Rules engine: transparent YAML — no ML.
